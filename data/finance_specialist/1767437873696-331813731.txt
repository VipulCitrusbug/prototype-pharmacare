 What the Dashboard Should Show (Bevel Reference Explained)
Inspired by Bevel’s UX philosophy, the dashboard should answer one question first:
“How am I doing today — in simple terms?”
Top Section (Hero Area)
* Daily State Card
   * Status: Steady / Improving / Needs attention
   * Short sentence:
“Your vitals are stable today. Sleep quality is improving.”
Middle Section (Insights, Not Data Dumps)
   * 2–3 Key Insight Cards
   * “Your BP trends lower on active days”
   * “Sleep dropped slightly last night”
   * No charts by default — charts open on tap
Lower Section (Action-Oriented)
   * Today’s tasks
   * Medications due
   * Care plan nudges
Design Rules (from Bevel)
   * No red panic screens
   * No medical jargon first
   * Charts are secondary, insights are primary
   * Always explain why something matters

                     * Activate / deactivate organization
                     * Set timezone, region, billing reference
                     * View organization health summary
System actions:
                     * Auto-generate org ID
                     * Apply default policies
                     * Initialize audit scope

                     * Org health score (engagement, alerts, device reliability)
                     * Predictive scaling warnings (“Clinic nearing patient capacity”)

4. Program & Care Model Setup
Admin defines:
                     * RPM programs
                     * Enrollment criteria
                     * Program duration
                     * Default alert thresholds
Used later by:
                     * Providers (care plans)
                     * Patients (program enrollment)
Enhancements:
                     * AI-assisted threshold recommendations (based on historical data)
                     * Simulation preview (“Estimated alert volume per 100 patients”)
                     * Explainable rationale for suggested defaults (non-autonomous)

5. Provider Assignment & Mapping
Admin:
                     * Assign doctors & care coordinators to clinics
                     * Set provider capacity limits
                     * Map providers to programs
Rules:
                     * No orphan patients
                     * All providers must belong to a clinic
Changes are audit-logged
Enhancements:
                     * AI-based capacity balancing suggestions
                     * Risk alerts for overload (“Coordinator exceeding safe caseload”)
                     * What-if previews before applying changes
________________


3️⃣ User & Access Control
6. User Management
Admin can:
                     * View all users (Patients, Providers)
                     * Activate / deactivate accounts
                     * Force logout / reset credentials
                     * View user activity & last login
Safety:
                     * Soft delete only
                     * No hard delete without compliance workflow
Enhancements:
                     * AI-driven anomalous activity detection (account misuse, unusual access)
                     * User risk flags (high failed logins, dormant privileged accounts)
                     * Plain-language explanations (“Unusual access pattern detected”)
________________


7. Role & Permission Configuration
Admin:
                     * Defines role capabilities (RBAC)
                     * Controls access per role:
                     * Clinical write
                     * Alert resolution
                     * Messaging
                     * Data export
Even with 1 admin, this prevents future rework.
Enhancements:
                     * AI-assisted permission impact preview
“This change will affect 12 providers and 340 patients”
                     * Misconfiguration warnings (least-privilege violations)
                     * Bevel-style clarity (plain English summaries of permissions)
________________
